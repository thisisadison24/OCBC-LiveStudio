Below is the full functional and content spec for "Live Studio" — a back-office tool
for managing and moderating OCBC's live streaming sessions, on-demand video uploads,
and community discussion threads, plus an analytics view over all three. Treat this as
the product spec, not literal markup to copy — adapt it to our stack (React/Vue/etc.,
whatever this repo uses) and our existing components.

PRODUCT OVERVIEW
-----------------
Live Studio is an internal moderation and analytics console with six sections,
reachable from a persistent left sidebar: Overview, Uploads, Live, Threads, Hot Topics,
Analytics. It is used by content/compliance teams to:
1. Review and approve/reject user-submitted content before it goes live.
2. Manage on-demand video uploads and live streaming sessions (create, tag, schedule,
   set visibility).
3. Moderate community discussion threads (verify submissions, manage the published
   feed, manage tags).
4. Monitor trending market discussion topics ("Hot Topics") with sentiment signal.
5. Review performance analytics across all content types.

NAVIGATION / IA
---------------
Sidebar sections, in order:
1. Overview — cross-section leadership snapshot.
2. Uploads — on-demand video content management.
3. Live — live streaming session management.
4. Threads — community submission moderation, live feed management, and tag curation
   (three sub-tabs: Verification Queue, Live Feed, Tags).
5. Hot Topics — read-only trending market insight feed, separate from Threads' "Tags"
   tab. Placed directly below Threads in the nav.
6. Analytics — deeper performance/engagement/moderation-health reporting, with its own
   sub-tabs for Live / Uploads / Threads.

Each top-level nav item swaps the visible page content; the active item is
highlighted.

DESIGN LANGUAGE (adapt to our design system; use this if we don't already have one)
-------------------------------------------------------------------------------------
- Dark theme: near-black background (#0A0B0D page bg, #141517 card surfaces), soft
  off-white text (#F5F3EE primary, #B3AFA4 muted secondary), thin 1px borders
  (#232529 / #33363B).
- Brand accent: a red (#D42B41, hover #FF8FA0) used for primary buttons, active nav
  state, and the brand mark.
- Status colors: amber (pending), green (active/approved/live), teal (approved/
  secondary accent), red/danger (flagged/rejected).
- Display font for headings/numbers (something like Sora — geometric, semi-bold to
  bold), body font for UI text (something like Inter), monospace font for
  timestamps/metrics/counts (something like JetBrains Mono).
- Card pattern: rounded corners (~10–16px radius), 1px border, a thin 3px colored top
  accent stripe indicating status/category.
- Small colored status dots and pill-shaped badges (pending/active/approved/rejected/
  flagged) used consistently across tables and cards.
- Custom searchable/selectable dropdown component (not a native <select>) used for all
  table filters and form pickers, with a trigger button + floating menu + checkmark on
  the selected option.
- Modals: centered overlay, header with title + close button, scrollable body, footer
  with right-aligned action buttons.
- All header/label text (page titles, panel headings, stat card labels, table column
  headers, chart titles) is Title Case, e.g. "Completed Live Sessions (30d)",
  "Content by Section", "Weighted Attendance Rate" — not sentence case, not literal
  camelCase.

PAGE 1: OVERVIEW
-----------------
Purpose: leadership snapshot summarizing Live, Uploads, and Threads in one view.

- Top stat row (4 cards): Pending Review, Live Now, Flagged, Avg Review Time — computed
  across both uploads and live content combined.
- Three stacked sections, each with a heading + description, a row of 3 KPI stat cards,
  and one chart:
  1. "Live" — KPIs: Completed Live Sessions (30d), Total Registrations, Weighted
     Attendance Rate. Chart: a 14-day line/area chart of daily registrations.
  2. "Uploads" — KPIs: Unique Upload Viewers (30d), Avg Watch Time, Upload Completion
     Rate. Chart: a donut chart titled "Content by Section" showing the share of
     published uploads by section (Markets, Wealth, SME, Other).
  3. "Threads" — KPIs: Active Threads (30d), Active Thread Viewers, Thread Engagement
     Rate. Chart: a donut chart titled "Submissions by Status" showing Approved/
     Rejected/Flagged share.

- Donut chart requirements (apply to both donut charts here and anywhere else a donut
  is used):
  - The donut sits beside its legend (legend to the right), not below it — laid out as
    a horizontal row, centered within the card.
  - The donut has a hollow center showing the grand total as a large bold number, with
    a small muted label underneath (e.g. "1,240" / "Published Uploads"). Make sure this
    center label text is short/small enough that it does not visually overlap or get
    clipped by the ring itself — keep it inside the donut's inner hole.
  - The legend is a vertical list: colored swatch, category label, then the absolute
    count and percentage (e.g. "Markets   521 · 42%"), right-aligned value. All legend
    text uses the same muted grey tone — no bold/high-contrast numbers standing out
    from the rest of the legend.

PAGE 2: UPLOADS
-----------------
Purpose: manage on-demand video content.

- Page header with "New Upload" primary button (opens the shared content-creation
  modal, see below).
- Stat row: Pending Review, Published (active+approved), Flagged, Avg Review Time.
- "Uploads Log" panel: a searchable, filterable table.
  - Search box (matches title/owner/tags).
  - Status filter dropdown: All Statuses / Pending Review / Active / Approved /
    Flagged / Rejected.
  - Table columns: Title (with a small type icon), Owner, Section, Tags (as chip
    list), Status (as colored badge), Description (truncated with ellipsis + full text
    on hover).
  - Clicking a row opens the shared Content Detail modal (see below).

PAGE 3: LIVE
-------------
Purpose: manage live streaming sessions. Same structure as Uploads, but for live
sessions:
- "New Live Session" primary button.
- Stat row: Live Now, Pending Review, Flagged, Avg Review Time.
- "Live Log" panel with the same search + status filter (statuses: Pending Review,
  Live Now, Approved, Flagged) + table shape as Uploads.
- Same shared Content Detail modal on row click.

SHARED: New Upload / New Live Session modal
--------------------------------------------
One modal reused for both Upload and Live creation (title changes based on context),
with three tabs:
1. Content — drag-and-drop file dropzone (video/image, with file-type/size hint),
   thumbnail upload-or-auto-generate row, Title, Description, Owner picker, Section
   picker, Tags input, Region picker, Language picker.
2. Visibility & Comments — publish visibility as selectable cards: Public / Restricted
   (with conditional client-tag and CIF-number fields) / Private; plus an "Allow
   Comments" toggle.
3. Schedule — date + time pickers, timezone picker, and a toggle for holding content
   private until the scheduled time (label adapts: "Premier" for uploads, "Hold for
   scheduled start" for live).
Footer: Cancel / Save as Draft / Submit for Review.

SHARED: Content Detail modal
------------------------------
Opens for any Uploads/Live row regardless of status. Two-column layout:
- Left: video placeholder box, and a transcript/description block below it (heading
  becomes "Video Transcript" when a transcript exists — with any compliance-flagged
  phrase highlighted inline — otherwise "About This Content" showing the plain
  description).
- Right: "Review Comments" (only shown for flagged items, with existing comments +
  an add-comment input) and an "Audit Trail" (a vertical timeline of status events:
  submitted → awaiting review → auto-flag triggered → assigned to compliance →
  reviewer comment → resolution), generated dynamically from the item's status.
Footer: Edit / a primary action button whose label is "Mark Complete" for flagged
items or "Close" otherwise.

PAGE 4: THREADS
-----------------
Purpose: moderate community-submitted market discussion, manage the public feed, and
curate tags.

- Stat row: Pending Review, Live Posts, Flagged for Compliance, Featured Tags.
- Three sub-tabs (segmented control):

  1. Verification Queue — submissions awaiting moderation.
     - Filters: search box, Category dropdown (All / Market News / Discussion /
       Earnings / Personal Finance), a Verified-status dropdown (All Users / Verified
       Users / Non-verified Users), and a Status dropdown (All / Pending / Approved /
       Rejected / Flagged, default "Pending").
     - Feed of cards, each showing: avatar/initials, author name + a "Verified" tier
       badge for verified users, submission time, category tag, post content, an
       optional attached-chart placeholder, an optional flag-reason note (for flagged
       posts), a status badge, and inline Reject / Approve buttons.
     - Approving a submission moves it into the Live Feed (prepended, "just now").
     - Clicking a card opens a Submission Review modal (author header, flag reason if
       any, full content + attachment, a moderator-note textarea, Reject / Approve &
       Publish footer buttons).

  2. Live Feed — posts already published to the app.
     - Filters: search box, a post-type dropdown (All Posts / Featured / Reported by
       Users), and the same Verified-status dropdown (All Users / Verified Users /
       Non-verified Users) used in the Verification Queue.
     - Cards show engagement stats (views/likes/comments), a "★ Featured" badge when
       pinned, a report-reason note when reported, and Remove / Feature-Unfeature
       action buttons.

  3. Tags — hashtag/category management (this tab is explicitly named "Tags", not
     "Discussion Topics" or "Topics").
     - "+ New Tag" button opens a small modal with Hashtag and Display Label fields;
       submitting prepends a new tag card (0 posts, unfeatured).
     - Grid of tag cards: hashtag, display label, post count, and a "feature on app
       home" toggle switch that shows a "★ Featured" badge when on.

Both the Verification Queue and Live Feed's author-tier data model needs a `tier`
field (e.g. "Verified Investor" vs "Community") so the verified/non-verified filter
can work identically in both places.

PAGE 5: HOT TOPICS (new, distinct from the Threads "Tags" tab)
------------------------------------------------------------------
Purpose: a read-only feed of trending market discussion themes with sentiment signal
— aimed at surfacing what's currently trending for editorial/market-insight purposes,
as opposed to the Tags tab which is about curating the taxonomy users post under.

- Stat row: Trending Topics (count), Total Mentions (7d), Bullish Topics (count),
  Bearish Topics (count).
- A sentiment filter dropdown: All Sentiment / Bullish / Bearish / Neutral.
- Grid of trending-topic cards, each ranked ("#1 Trending", "#2 Trending", ...),
  showing: title, associated hashtag, a sentiment badge (Bullish/Bearish/Neutral,
  color-coded green/red/grey), a short market-insight blurb, mention count, week-over-
  week momentum (▲/▼ percentage, colored), and related sub-tags as chips.

PAGE 6: ANALYTICS
-------------------
Purpose: deeper reporting across Live, Uploads, Threads for engineering/analytics
teams.

- A filter bar: Date Range, Content Section, Creator or Host, User Segment, Content
  Status (options for the Content Status dropdown change depending on which sub-tab is
  active).
- Three sub-tabs (segmented control): Live / Uploads / Threads.

  Live tab:
  - 4 KPI cards with a hover "?" tooltip explaining the metric and a vs-previous-
    period delta: Completed Live Sessions, Total Registrations, Weighted App Access
    Rate, Weighted Attendance Rate.
  - A definition callout explaining that "weighted" means combined totals across
    sessions rather than a simple average, so larger sessions carry proportionate
    weight.
  - A registration-to-attendance funnel (6 stages: Session Page Views → Registrations
    → External App Access → Live Attendance → Watched 5+ Min → Chat or Poll).
  - A "Live Session Performance" table (Session, Registrations, App Access,
    Attendance, Avg Watch, Engagement), clickable rows link to per-session detail.

  Uploads tab:
  - 4 KPI cards (Unique Upload Viewers, Average Watch Time, Upload Completion Rate,
    Upload Engagement Rate) with deltas.
  - Two side-by-side charts: a views+engagement trend line chart, and a viewer-
    retention curve (% of viewers remaining at 0/25/50/75/100% of video progress).
  - A "Top Uploads" table (Upload, Views, Avg Watch, Completion, Engagement, Flag
    Rate).
  - An "Upload Performance by Section" breakdown: per section, paired bars comparing
    % of uploads published vs. % of views received, a computed "view opportunity"
    (view share minus upload share, colored + for positive / − for negative), plus
    completion and engagement rate. Include a definition note explaining "view
    opportunity."

  Threads tab:
  - 4 KPI cards (Active Thread Viewers, Active Threads, Thread Engagement Rate,
    Average Replies per Thread) with deltas.
  - Two side-by-side charts: a thread-activity trend line chart (new threads/replies/
    engaged users) and a "Thread Lifecycle" horizontal bar breakdown (Active/
    Declining/Dormant/Flagged submission counts).
  - A "Most Discussed Threads" table (Thread, Views, Replies, Contributors,
    Engagement, Flag Rate).

- Below all three tabs, a shared "Content Health and Moderation" section: a grid of
  secondary metrics (Flag Rate, Reports per 1,000 Views, Average Response Time,
  Average Resolution Time, Pending Review Backlog, Misleading Information rate,
  Repeat Offender Rate, Resolved Within SLA).

DATA MODEL (adapt names/types to our existing backend/API conventions)
--------------------------------------------------------------------------
- Content item (Upload or Live): title, owner, section, tags[], status (pending |
  active | approved | flagged | rejected), description, optional transcript (with
  flagged phrases marked for highlighting).
- Submission (thread post pending review): author, initials, tier ("Verified
  Investor" | "Community"), category, submittedAt, content, optional hasChart,
  status (pending | approved | rejected | flagged), optional flagReason.
- Live feed post (published thread post): author, initials, tier, category,
  publishedAt, content, optional hasChart, views, likes, comments, featured (bool),
  reported (bool), optional reportReason.
- Tag: hashtag, displayLabel, postCount, featured (bool).
- Hot topic: title, hashtag, sentiment (bullish | bearish | neutral), mentionCount,
  weekOverWeekChange (signed %), blurb, relatedTags[].

IMPLEMENTATION NOTES
---------------------
- All stats/tables/feeds should be driven by data (arrays/API responses) and re-render
  on filter/search change — not hardcoded per filter combination.
- Every list/table with a search box needs an explicit empty state ("No … match these
  filters.").
- Reuse one generic status-badge / tag-chip / stat-card component across all pages
  rather than duplicating markup per page.
- Match whatever data-fetching, state management, and component patterns already exist
  in this codebase; this document describes product behavior, not a required tech
  stack.
